## What landed this session

### Opus 5.5 (`c101a81d2`)

Reported symptom: a 400 on every Opus 5.5 request, saying Claude Code 2.1.257
is too old and to run `claude update`. The operator had already updated via
homebrew and the error persisted.

The advice in that message cannot work. jcode does not shell out to the Claude
Code CLI, it advertises its own hardcoded version string. Two independent
defects, both required:

- Three attribution constants pinned at `2.1.257`, bumped to `2.1.281` (the
  version actually installed, not the `2.1.280` floor named in the error).
- `claude-opus-5-5` was not in `AVAILABLE_MODELS` at all.

Model id, pricing and context window were read out of the shipping 2.1.281
binary rather than guessed. It carries the literal id and release notes stating
1M context and $4/$20 per Mtok with $0.20 cache reads. Also corrected
`cch=33f85` to `cch=00000`, which is what the 2.1.281 attribution builder emits
for first-party subscriber requests.

Verified live, not just compiled:

```
jcode run --model claude-oauth:claude-opus-5-5 'Reply with exactly: OPUS55 OK'
  -> OPUS55 OK
```

Capability tables needed no change and that was checked rather than assumed:
the version parser reads `5-5` as (5,5), giving Native1M, 128K output and the
full effort ladder.

### Dotfile and secret-store protection (`6d67db559`)

Probing after H3 found protected *directories* guarded while the files that
make them worth guarding were not. `rm ~/.bashrc`, `rm -rf ~/.local/share/keyrings`
and `rm ~/.netrc` were all **Low** (silent), while `rm -rf ~/.config` was already
Catastrophic.

Two tiers, because the losses are not equivalent: secret stores are
Catastrophic (unrecoverable, re-issuing every key), shell init files are
Confirm (recoverable work, but silently reconfigures every future shell).
Redirects and `truncate` route through `classify_target`, so
`echo '' > ~/.zshrc` is covered without touching the verb tables.

## Open items, in priority order

1. **`--model` alone does not imply the model's provider.** Pre-existing and
   unrelated to either commit. With `default_provider = "opencode-go"` in
   config, `jcode run --model claude-opus-5-5` sends a Claude id to a non-Claude
   route, which rejects it as an invalid model. The same happens for
   `claude-opus-5` and `claude-fable-5-1`, so it long predates Opus 5.5.

   Workarounds, both verified: `--provider claude --model claude-opus-5-5`, or
   the prefixed form `--model claude-oauth:claude-opus-5-5`.

   `provider_for_model_with_hint` already maps any `claude-` id to `claude`
   correctly, so the fix belongs at the call site that prefers the configured
   default over model inference, not in the inference table. Worth fixing: the
   natural spelling is the broken one, and the resulting error names the model
   rather than the routing, which points the user at the wrong problem.

## Working agreements to carry forward

- Explicit approval before pushing, and before any change to what a gate means.
- Fix at the source, never by loosening a gate. Raising a baseline is acceptable
  only when the baseline is demonstrably stale, and the commit must say what it
  absorbs.
- Measure, don't assume. Every claim in a commit message should be something
  actually run. Both fixes this session came from reading the shipping binary
  and probing the classifier, not from guessing.
- Don't let a safety gate become noise. Over-firing trains users to bypass it,
  which is why the routine-work test matters more than new coverage. It caught
  a wrong assertion again this session.
